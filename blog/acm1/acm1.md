# 贪心算法 从认识到提升

> 其实，我并不认为把这类思想通称为贪心算法是正确的，因为我们生活中，无时无刻不在"贪心"

显然，这里的"贪心"并非是指盲目的贪心，而是在合理范围内，最大化收益的贪心。

### 经典贪心思维

我们称一件事情的某个 **状态** 约束下，使得 **代价/收益** **最小/最大化** 的这个程序算法流程，为**贪心算法**。
显然我们的想法就是，现在挑一个收益最大的，能保证最终收益最大
下面将举个例子

#### 问题1

```
选数问题
10个数，选5个数，使得这五个数的和最大，怎么选？
```

显然，这你看一眼就知道，但我希望我们还是系统地分析一下这个问题：

###### 状态约束

1. 选5个数
2. 每个数选一次

###### 结果要求

最大化5个数的和

###### 分析

显然找五个数，就能满足约束条件1,下面的五个数，显然，找最大的五个数e即可

#### 问题2

```
给你 n 个任务，每个任务需要 1 彭元 的经费，但要求你的 彭元 务必 大于等于 m[i] 才能做这个任务。
问你最多能做几个任务？
```

###### 状态约束

1. 每个任务需要个经费门槛
2. 每个任务花1**彭元**

###### 要求

多做点任务

###### 分析

显然，如果你有5**彭元**，现在有两个门槛分别为5,4的任务，显然先做门槛大的，则门槛小的也能做，而先小的，大的就不一定能做了。这个道理，我们的想法是按门槛从大到小来做任务，当然肯定有做不了的，跳过就行，如果跳过它，显然对于结果来说，就是拿前面一个任务来换这个任务，是相同的

### 反悔思维

当然现实中不存在反悔，这里的反悔是指在决策中，你肯定有思考到死角的时候，假如你在一道问题前面有某个地方思考出错了，你就需要“反悔”——这个地方改正下，再来继续思考

#### 问题3

```
和问题2差不多，但换个说法，并升级了：
给你 n 个作业，显然作业有ddl，然后你每个作业要花的时间也不太相同。
假设你不能完成所有的ddl，你的想法大概率是最大化结果的好坏。
我们假设所有作业是相等的，且不存在有哪个作业必须完成的情况，即我们只需要最大化作业的完成数。
```

###### 状态约束

1. 每个任务有ddl
2. 每个任务耗时不同

###### 分析

1. 首先ddl，我们肯定得把先结束的做了，因为结束后再做就不行了
2. 一定时间内，你肯定做一堆耗时小的任务，完成的任务量更多
   这上面是两个贪心思路

我们发现，这俩约束条件不是包含的关系，耗时小可能ddl近也可能远，这俩毫不关联的变量(ddl,耗时)，二者不可兼得。这时候考虑，我们先满足其中一个贪心思路，然后照着另一个贪心思路进行反悔。

对于这个题，我们发现，思路1是约束思路2的,因为思路1的ddl是强制性的，而思路2单纯是为了结果而设计的。我们说过，贪心算法的决策要遵从状态约束，因此我们优先处理 思路1,按照ddl排序，这时候按照 问题2 的思路来即可

但是显然，如果你找了一堆大的，可能2个任务就填满了。因此我们想：已经经过的这些，我们选一些小的。

假设我们就ddl排序后挨个看，可能有选不上的，这时候考虑了：要不要1换1？问题2确实1换1不用考虑，但这里1换1,你想想，你是考虑做耗时长的还是耗时短的？显然这里就有一个贪心策略思路2的应用：满足ddl的前提下，尽量耗时大换耗时小的。

因此思路明确了，ddl排序然后走，能做的先做了，不能做的，看看以前做的，有耗比它长的，就换

### 证明思维

显然有的时候，数学证明大于一切

#### 问题4

```
一个工厂有a,b两个机器，物品要先经过a机器加工，而后才能去b机器加工，现在有多个待加工物品，怎么安排，时间更少？
机器加工需要时间，同一个物品的两个加工的时间可能不同
```

显然如果你盲目地按照某个机器的加工序列肯定是不行的，可以自行举反例证明

那么，这本质是一个排序问题，但排序的依据怎么办呢？

因此我们考虑，设物品A比物品B先加工时，需要时间更少，另设B比C先加工，需要时间更少，你能够推断出来：A比C先加工时，时间更少（可自行证明）

这样我们按这个优先级，贪心地进行排序。

当然，为什么正确？我们来证明一下：前面有 $A<B$（这里指的是A比B先加工时，用时更少）,$B<C$,那么$A<C$,显然这样排序，能得到一个最小值A,使得其“小于”其他所有物品，这样无论A在哪个物品后面，A和前面的那个物品缓一下，则一定能使得用时更少。以此类推，按这个顺序排，显然能使最终结果更优

### 取代贪心

这是一种解决算法问题的方法，就是对于以多个状态之间差异为节点的问题，我们可能有多个末状态对应一个初状态，我们的想法是，让一个末状态取代初状态，作为新的初状态，这样存在更好的末状态时，它能够有机会取代这个状态对

有时候和反悔贪心打联合

#### 问题5

```
FX战士发愁鸭，现在有足够的钱。现在他一个外汇都没有，所以他来炒股。
通过时光机，接下来的 n 天，每天的股价他都已经知道了。

每天它可以从3个选择里选择1个来做，只能选1个！！！
1. 买一股
2. 卖出一股，前提是有股票
3. 啥也不做等明天再说

我们假设股票在一套内就是那个价，只有到第二天才改价格，所以忽略掉一天内股价的浮动
同时，多一事不如少一事，所以发愁鸭希望n天过后，他没有任何一个股票
你也能猜到了，这个题问的是：怎么行动，赚钱更多？
```

![久留美图片](blog3.jpg)

###### 状态约束

1. 务必按天数依次进行
2. 买多少卖多少

###### 结果要求

最大化利润

###### 分析

遵从状态约束1,我们按时间顺序依次进行，现在分析每一天：

首先我们要想，行动3=行动1+行动2,所以我们只管行动1和行动2

那么假设前面有一堆价格买的股票，我们想，我们肯定找个比它低的，卖出去。

但有两个问题：

1. 状态约束2怎么实现？
2. 假设后面有价格更高的，且万一最优解中，后面价格更高的，选中了这次选的，前面价格比他低的股票呢？

对于2,我们选择先记录下卖出去的价格，然后我们假设后面有更好的，需要换掉他的，那么我们可能要做的，就是买进原来那个，然后这天抛出。显然，那么这一天先卖后买可以省略为：后来那一天卖出了前面某天买的股票，这一天等价于啥也没干。

那么来解决状态约束2,前面提到行动1+行动2=行动3,我们先假设每天的股票都买了，把总利润扣钱，后续如果没有卖出这些股票，那么显然，我们本就不需要买入他们，后续利润加回去就好，这样当作行动3了。

###### 流程总结

按天数走，首先看看要不要卖股票，即从以前的股票中，贪心地选个最小值，然后假设再买入它；

上述流程走完后，买一张当天的股票。

之后有一天可能会选它，这时候取代就行了。

最后清算，堆里的算作卖出，加入利润就行了

> 你可能问，这样做，有一个天，既卖出了前面一张股，又被后面某天卖呢？
>
> 答：有这种情况，后面某天为什么不选前面的呢？而且只看答案，这个本质就是取代。
> 这个方法的话，对于每个股票：
>
> 1. 最终有俩个 价格等于这个股票的（假设就是一个取代，一个买入），显然买入再卖出等价于没干事，取代不用说了
> 2. 最终有一个 ，你可以自选一个当作买入的，本质没啥事，另一个当作被取代或者根本没干事
>    也可以假定一个是取代了前面的，一个被后面卖出了，本质后面取代，另一个扣了钱再卖出等于没买
> 3. 最终零个，被取代一个不用说了，当没发生，另一个直接卖

总之，这类想法是，它取代前面的状态，而本质上后续状态再取代时，取代的是前面的状态而非它。

下面是这个题思路的一个关键的代码

```cpp
std::priority_queue<int,vector<int>,greater<int>>q;
int m=0;
for(int k=1;k<=n;k++){
    if(q.size()&&q.top()<a[k]){
        q.pop();
        q.push(a[k]);
    }
    m-=a[k];
    q.push(a[k]);
}
while(q.size()){
    m+=q.top();
    q.pop();
}
```

### 总结

贪心无疑就是考虑整体最优，而不是盲目的局部最优。

这里贪心是在决策上的贪心，而非实际上的反悔。
